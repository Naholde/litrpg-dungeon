# План разработки «LitRPG: Подземелье Системы» (4.0, с нуля)

Исходное описание игры — [docs/VISION.md](docs/VISION.md). Оно задаёт направление, но не является жёстким правилом.
Полное описание старого мода 3.3 — [docs/IDEAS.txt](docs/IDEAS.txt): **источник идей, а не руководство** (классы, хранители,
загадки, добыча, бестиарий). Берём оттуда идеи, а не устройство и не цифры.
Ниже — решения владельца (ответы на 30 вопросов), устройство проекта и порядок работ.

---

## 1. Решения владельца

| 18 | Урон по своим | Есть, но сниженный. |
| 19 | Хранители | Свобода, но каждый индивидуален. |

| 23 | Темы этапов | На усмотрение Claude. |

| 25 | Снаряжение | Броня + оружие + **4 слота** украшений (Curios). |
| 26 | Свойства | Случайные свойства у вещей. Передавать вещи можно свободно. |
| 27 | Божественные | Только из сложных секреток/нычек и с малым шансом с самых сложных хранителей. |
| 28 | Текстуры | 16×16, тщательно. |
| 29 | Музыка | Владелец пришлёт позже. **Напомнить, когда дойдём до музыки (фаза 9).** |

**Отличия от старого мода (IDEAS.txt), которые важно не перепутать:**
- Маны нет вообще: эликсиров маны, «+15% маны» и восстановления маны тоже нет. Свой ресурс (ярость, заряды, здоровье,
  облик, сферы) — только у классов, которым он нужен по идее.
- У класса 5–6 способностей, а не 12 на выбор. Значит, каждая способность важнее, и ни одна не может быть «просто уроном».
- Легендарки, классовые наборы и трофеи пересчитываем под ~30 классов и 4 слота украшений.

## 2. Почему старый мод ломался и что делаем иначе

| Беда в старом моде | Правило в новом |
|---|---|
| Описание навыка обещает одно, а код делает другое | **Навык = один Java-класс.** Подсказка в игре собирается из тех же полей, которые использует код. Отдельного текста с цифрами нет. |
| Цифры баланса спрятаны в коде, правка ломает механику | **Механика — в коде, цифры — в данных** (`data/litrpg/balance/*.json`). Команда `/reload` меняет баланс без пересборки. |
| Правка одной системы задевает другую | Отдельные модули с понятной связью (персонаж, бой, навыки, хранители, добыча, прохождение, карта). Модули общаются через события и интерфейсы, а не лезут друг в друга. |
| Баги находятся только в игре и поздно | **Автотесты**: GameTest NeoForge (навыки, урон, агро, вайп) и проверка карты. Сборка на GitHub Actions после каждого push. |
| Работало в одиночке, ломалось на сервере | Сервер решает, клиент только показывает. Каждый этап проверяется на выделенном сервере. |
| Хранители копировали друг друга | Общий каркас (разметка, фазы, неистовство), но у каждого хранителя свой класс и своя «идея». |
| Пересборка по кругу | Каждая фаза заканчивается проверкой, коммитом и записью в `HANDOVER.md`. Сделанное не переделываем без причины. |
| Цифры жили в трёх местах (данные, код, текст) и расходились | Один источник: коэффициенты навыка — в данных, код читает их, текст строится из них. |
| Каждый класс писал свой обработчик урона | **Метки со сроком** в ядре с первого дня: получаемый/наносимый урон, отражение, вампиризм, перенаправление. Один обработчик урона читает все. |
| Частые удары и стрелы «отскакивали» | Ванильная неуязвимость после удара явно сбрасывается для тиков навыков. |
| Отложенный удар считал силу в момент попадания | Сила отложенных ударов фиксируется в момент применения. |
| `.gitignore` с `run/` съел пакет `run` с кодом | Служебные папки в `.gitignore` пишутся от корня (`/run/`), пакеты не называются как служебные папки. |
| Клиент и сервер молча расходились | Версия сетевого протокола поднимается при любом новом пакете (проверяет тест). |
| Близнецы считались дважды | Всё «на хранителя» (волны, награды, победа) — один раз на бой, а не на сущность. |
| Карту ломали правки | Проверка проходимости карты встроена в сборку: не прошла — jar не собирается. |

## 3. Устройство проекта

```
src/main/java/.../litrpg/
  core/       реестры, конфиг, загрузка баланса (json → объекты), /litrpg команды
  player/     уровень, опыт, характеристики, роль, класс, ранги, StatBreakdown (один расчёт для боя и окна)
  combat/     урон, крит, уклонение, сопротивления, урон по своим, угроза (агро), провокация
  ability/    каркас навыка, откаты, чтение, прицел, ресурсы классов; classes/<роль>/<класс>/ — навыки
  boss/       BossBase, фазы, Telegraph (разметка), неистовство, узлы силы, волны, масштаб под группу
  mob/        бестиарий, ИИ отрядов
  loot/       редкости, свойства, генерация, личная добыча, Curios
  expedition/ лобби, печать, этапы, духи, вайп, разлом, сохранение (SavedData)
  world/      измерение, плитки карты, защита мира, механизмы (загадки, ловушки)
  client/     HUD, окна (персонаж, роль, класс, лавка), мини-карта, эффекты, анимации
  net/        пакеты
tools/        генераторы: карта, текстуры, данные; проверка карты
```

Подключаем: **NeoForge 1.21.1**, **GeckoLib** (анимированные модели), **Curios** (4 слота украшений), **Patchouli** (Кодекс), JEI (по желанию).

## 4. Порядок работ

Каждая фаза = рабочая сборка + проверка в игре + коммит + push + запись в `HANDOVER.md`.

### Фаза 0. Фундамент (1 сессия)
- Проект NeoForge 1.21.1, JDK 21, Gradle, GitHub Actions (сборка + тесты).
- Загрузка баланса из json, `/reload`, dev-команды, запуск выделенного сервера для проверки.
- Каркас автотестов (GameTest).
- **Готово, когда:** пустой мод собирается, запускается в клиенте и на сервере, тест проходит.

### Фаза 1. Персонаж
- Уровни 1–50, опыт `100 + 90 × ур^1,85`, 5 характеристик (×0,3 за очко), роли (танк / боец / поддержка), окно выбора роли.
- Здоровье числом и полосой вместо сердец, без голода. Окно персонажа (K): «Статус», «Навыки», «Расчёт».
- **Готово, когда:** выбираешь роль, качаешься командой, цифры в окне совпадают с реальным уроном и здоровьем.

### Фаза 2. Бой
- Урон, крит, уклонение, броня. Посох — новое оружие.
- **Угроза (агро)**: таблица угрозы, провокация танка, значок над тем, на ком агро, и в рамках группы.
- Урон по своим (сниженный). Прицельное лечение: рамки группы, Ctrl+1…5.
- Рывок (Alt), панель 6 ячеек (Z X C V B G), полоса чтения.

### Фаза 3. Навыки и классы
- Каркас навыка: подсказка из кода, ранги, откаты, чтение, ресурсы классов (ярость и др.), эффекты.
- 3 навыка новичка для каждой роли.
- **Список ~30 классов** (по ~10 на роль) с идеей в одну строку и 5–6 способностями — на утверждение владельцу до кода.
  Основа — идеи из IDEAS.txt (Стражник, Кровавый рыцарь, Законник, Гравитон, Зерцало, Стриж, Монах, Астромант, Снайпер,
  Хронолог, Оракул, Алхимик…) плюс новые, чтобы у каждой роли было ~10.
- **Первые 3 класса** (по одному на роль), полностью: способности, ресурс, эффекты, звуки, тесты.
- Выбор класса на 10 уровне: Система предлагает 3 класса по стилю игры; класс уникален в отряде.
- Затем остальные классы — пачками по 3 (по одному на роль), каждый с тестом «описание = поведение».

### Фаза 4. Каркас хранителей + полигон
- BossBase: фазы, подготовка навыков, разметка на полу (круг, кольцо, конус, полоса, «на разделение»), неистовство, щит, оглушение, узлы силы, подручные, перенос в другой зал, масштаб от числа игроков на старте.
- GeckoLib: анимации замаха и удара — каждый удар читается глазами.
- **Полигон**: тестовая арена и один пробный хранитель. На нём проверяем, что танк, лекарь и боец нужны все.
- **Это главная точка проверки**: если на полигоне бой интересный, дальше идём массово.

### Фаза 5. Добыча и торговец
- 6 редкостей (обычная → божественная, каждая кратно реже). Случайные свойства, 4 слота Curios, личная добыча, свободная передача.
- Трофеи хранителей — свой список у каждого. Монеты, торговец (лавка, смена класса, сброс рангов), свиток забвения.

### Фаза 6. Бестиарий
- Монстры этапов (модели GeckoLib, 16×16), ИИ отрядов: у монстров тоже роли (защитник, стрелок, лекарь).
- Мини-хранители.

### Фаза 7. Прохождение
- Измерение `litrpg:dungeon`, Преддверие, печать у врат (3–5 игроков), отряд, этапы, разлом.
- Духи и воскрешение, вайп этапа, спасение из пропасти/лавы, защита мира (ломать только `litrpg:breakable`).
- Точный опыт этапа (ровно 10 уровней), награда выдаётся один раз (без лишнего опыта после вайпа).

### Фаза 8. Карта (этап за этапом)
- Генератор карты + `check_dungeon` (проходимость, двери, засады).
- **Этап 1 целиком** (залы, загадки, ловушки, тайники, 3 хранителя) → проверка → затем этапы 2–5.
- Каждый хранитель — свой класс, своя идея; финальный хранитель этапа переносит бой в другой зал.
- Загадки: в том числе на разделение группы и текстовые. Божественные вещи — в самых сложных секретках.

### Фаза 9. Сюжет, звук, Кодекс
- Ненавязчивый сюжет: голос Системы, записки, реплики хранителей, титры.
- **Музыка владельца** у хранителей (напомнить и попросить файлы) + фон этапов.
- Кодекс (Patchouli): правила, этапы, хранители с тактикой, классы, бестиарий — собирается из данных автоматически.

### Фаза 10. Визуал
Всё, что игрок видит в бою, должно читаться глазами и выглядеть сделанным нарочно, а не «общей
вспышкой на все случаи».

- Способности классов — у каждой своя анимация и своя модель. Замах, применение и попадание —
  разные движения; руки и оружие участвуют. Ни одна способность не делится анимацией с другой.
- То, что класс оставляет в мире, — настоящий объект. Пример: тотем шамана — проработанная модель
  GeckoLib, стоит на месте, рисует на земле радиус своего действия, имеет здоровье, и враги могут
  его сломать (сломали — бафф пропал). Так же знамёна, ловушки, купола, зеркала, печати,
  призванные помощники — каждый со своей моделью, радиусом и прочностью.
- Хранители: у каждого удара своя анимация под его разметку (замах читается заранее), переход фазы —
  отдельная анимация, неистовство и смерть — свои. Ни один хранитель не повторяет движения другого.
- Монстры: бег, атака, получение урона, смерть и особенность вида (плевок, прыжок, луч лекаря, щит
  стража) — всё анимировано; 31 вид, у каждого узнаваемый силуэт и повадка.
- Значки навыков 16×16, нарисованные, по одному на каждую способность и метку — вместо заглушек.
- Эффекты: частицы, свет и цвет под идею класса (общий набор форм — в fx/), следы снарядов,
  попадания, лечение, воскрешение, смерть. Разметка на полу — аккуратная и одинаково понятная
  у всех хранителей.
- Отклик на экране: крит, уклонение, блок, щит; полоса чтения с названием способности; ровные
  рамки группы и хранителя.
- Модели и анимации — генераторами (tools/gen_models.py), текстуры и значки — tools/gen_textures.py;
  png руками не правим.
- Автотест: у каждой зарегистрированной способности, вида существа и хранителя есть модель,
  анимация и значок — чего-то нет, сборка падает.
- **Готово, когда:** по экрану видно, какая способность применена и кем, без чтения чата; любой
  объект класса можно найти в мире, понять его радиус и сломать.

### Фаза 11. Баланс и плейтесты
- Проходы группой, правка json-баланса без пересборки, финальная настройка под ~3 часа.

## 5. Как проверяется каждая фаза
1. `gradlew build` — сборка и автотесты (то же самое на GitHub Actions).
2. Запуск на выделенном сервере + клиент; dev-команды и скриншоты.
3. Сборка jar → папка mods в TLauncher.
4. Коммит, push, запись в `HANDOVER.md`.
